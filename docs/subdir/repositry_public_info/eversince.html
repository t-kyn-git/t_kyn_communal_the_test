This diagram illustrates a standard web application architecture using Nginx as the web server, Django as the application framework, and SQLite as the database. It visualizes the flow of how user requests are processed and returned as web pages.

Architecture Explanation

    User's Browser (Client): This is the starting point for a user to access the website. An HTTP request is sent from here.
    Nginx (Web Server / Reverse Proxy):** Acts as the gatekeeper that first receives requests. It directly serves static files like images, CSS, and JavaScript at high speed. Meanwhile, requests that require dynamic processing are forwarded (proxied) to the back-end application server (Gunicorn).
    Gunicorn (WSGI Server): Receives requests forwarded from Nginx and is responsible for calling the main Django application via Python's standard interface (WSGI).
    Django Application (The Application Itself):
    Views: The "control center" of the application, which executes the necessary logic based on the request. It fetches data from the database, performs calculations, and coordinates the response.
    Models: The "blueprint" that defines the database table structure. Through Django's ORM (Object-Relational Mapper), it allows developers to interact with the database using Python code instead of writing raw SQL.
    Templates: The "presentation layer" that generates the final HTML displayed to the user. It creates dynamic pages by embedding data passed from the Views.
    SQLite (Database): This is where the application's data (such as user information, posts, etc.) is stored. Data is read from and written to the database through Django's Models.
